# 16g 미니 GPU — 최종 기획 및 상세 설명서

- 문서 종류: 기획서 및 기술 사양
- 프로젝트 이름: **16g**
- 대상 환경: Windows 데스크톱
- 명령어 수: 16개
- 논리 명령 크기: 36비트(4비트 OP + 16비트 입력 1 + 16비트 입력 2)
- 기본 그래픽 해상도: 256 × 256 셀
- 셀 확대율: 2 × 2 물리 픽셀
- 색상 형식: RGB565

---

## 1. 프로젝트 개요

`16g`는 16개의 OP 코드로 산술·비트 연산과 간단한 그래픽 출력을 수행하는 자동화 가능한 초소형 GPU/연산기다. 모든 명령은 동일한 입력 구조를 사용한다.

```text
<OOOO> <IIIIIIIIIIIIIIII> <JJJJJJJJJJJJJJJJ>
  OP             INPUT1              INPUT2
```

- `OP`: 4비트 명령 코드. `0000`부터 `1111`까지 총 16개다.
- `INPUT1`: 16비트 입력 값.
- `INPUT2`: 16비트 입력 값.
- 일반 연산의 결과 폭: 16비트.

기본 원칙은 다음과 같다.

1. 명령에는 입력이 정확히 두 개 있다. OP별로 입력의 의미는 달라질 수 있다.
2. 그래픽 명령은 VGA 창의 픽셀을 변경한다. VGA 창에 상태 메시지나 글자를 그리지 않는다.
3. 비그래픽 연산 결과와 오류 진단은 그래픽 창이 아닌 실제 텍스트 출력 채널로 전달한다.
4. `VGA`는 색상 계산이 아닌 픽셀 기록을 담당한다. `BLEND`와 `BRIGHT`는 색상 값을 계산하고, 이후 `SHFL`로 결과를 `VGA`에 전달할 수 있다.
5. 명령 세트에는 동적 메모리 할당이나 `LOAD`/`STORE` 같은 범용 메모리 명령을 두지 않는다. 화면과 결과 이력에는 사전에 크기가 정해진 고정 저장 영역을 사용한다.

## 2. 실행 모드와 사용자 인터페이스

### 2.1 인수 없이 실행

```bat
16g.exe
```

두 창을 연다.

- **콘솔 창**: 명령 프롬프트, 도움말, 입력 및 비그래픽 결과를 표시한다.
- **VGA 창**: 256 × 256 논리 셀 그래픽 화면을 표시한다.

대화형 콘솔은 한 줄씩 명령을 입력받아 즉시 실행한다. 프롬프트용 명령은 OP 코드가 아니며, GPU 명령 세트의 16개 슬롯을 사용하지 않는다.

예시:

```text
16g Mini GPU
Resolution: 256x256 cells
Cell scale: 2x2 pixels
Color format: RGB565
Type HELP for commands.

16g> 0001 0000000000001010 0000000000000011
0000000000001101
16g>
```

위 예시에서 `ADD(10, 3)` 결과는 13이다. 콘솔의 배너와 프롬프트는 텍스트로만 표시하며 VGA 화면에는 그리지 않는다.

권장하는 프롬프트 전용 명령:

| 명령 | 기능 |
|---|---|
| `HELP` | 입력 형식과 OP 도움말 표시 |
| `CLEAR` | VGA 화면 전체를 검정색으로 지움 |
| `RUN 파일명.16g` | 지정한 바이너리 명령 파일 실행 |
| `EXIT` | 대화형 실행 종료 |

이들은 프롬프트 기능일 뿐, `16g`의 4비트 OP가 아니다.

### 2.2 명령 또는 파일을 지정해서 실행

명령 입력이나 `.16g` 파일을 인수로 제공하면 **새 콘솔 창을 만들지 않고 VGA 창만 표시**하는 자동 실행 모드로 진입한다.

```bat
16g.exe 0001 0000000000001010 0000000000000011
16g.exe program.16g
```

직접 명령 실행은 명령 한 개를 실행한다. 파일 실행은 파일 안의 명령을 순서대로 실행한다. 비그래픽 결과는 `stdout`, 오류와 진단은 `stderr`로 기록한다. 호출한 프로그램이 이 출력 핸들을 파이프나 리디렉션으로 연결했다면 결과를 읽을 수 있다. 별도의 콘솔 창을 표시하지 않는다는 의미이지, 출력 데이터 자체를 금지한다는 뜻은 아니다.

유한한 명령 또는 파일 실행을 마친 뒤에도 VGA 창은 사용자가 닫을 때까지 표시한다. 따라서 자동화 프로그램은 GUI 프로세스의 종료 시점도 고려해야 한다. VGA 창을 닫으면 실행 프로세스를 종료한다.

> 그래픽 창만 표시하는 모드에서 프로그램을 탐색기에서 직접 실행하면 콘솔 결과를 눈으로 볼 수 없다. 숫자 결과를 확인하려면 대화형 모드로 실행하거나, 호출 프로그램에서 표준 출력을 수집해야 한다.

### 2.3 입력 형식

기본 모드는 4비트 OP와 두 개의 16비트 이진수 필드를 받는다. 필드 사이 공백은 구분용이며, 각 필드의 이진 숫자 수는 고정이다.

```text
0001 0000000000001010 0000000000000011
```

허용할 입력은 다음과 같다.

- 대화형 프롬프트에 명령 한 줄 입력
- 명령 한 개를 프로그램 인수로 직접 전달
- 바이너리 `.16g` 파일 전달

이진수 명령은 OP 4자리, 입력 1 16자리, 입력 2 16자리여야 한다. 잘못된 길이, 이진수가 아닌 문자, 누락 필드는 형식 오류다.

## 3. `-hex` 옵션

`-hex`는 이진 명령 입력과 이진 결과 표시를 16진수 형식으로 바꾼다.

```bat
16g.exe -hex
16g.exe -hex 01 000A 0003
16g.exe -hex program.16g
```

16진수 명령 한 개는 다음 세 필드로 표현한다.

```text
<OO> <IIII> <JJJJ>
 OP   INPUT1 INPUT2
```

| 필드 | 표현 | 허용 범위 |
|---|---|---|
| OP | 2자리 16진수 | `00`~`0F` |
| INPUT1 | 4자리 16진수 | `0000`~`FFFF` |
| INPUT2 | 4자리 16진수 | `0000`~`FFFF` |

예를 들어 다음 명령은 10과 3을 더한다.

```text
01 000A 0003
```

결과는 4자리 대문자 16진수로 표시한다.

```text
000D
```

기본 모드에서는 결과를 16자리 이진수로 표시한다. `-hex`에서는 결과를 4자리 16진수로 표시한다. 결과는 선행 0을 생략하지 않는다.

`-hex`는 텍스트 입력/출력 표시 모드다. **`.16g` 파일 자체를 ASCII 16진수 텍스트로 변환하지 않는다.** `.16g`는 항상 아래에서 정의하는 바이너리 형식이며, `-hex`는 파일 안의 명령을 실행할 때 결과를 표시하는 형식에도 적용된다.

## 4. VGA 창과 그래픽 형식

### 4.1 논리 해상도와 실제 크기

- 논리 화면: 256 × 256 셀
- 셀 하나: 가로 2 × 세로 2 물리 픽셀
- 논리 화면의 확대된 표시 영역: 512 × 512 물리 픽셀
- 좌표 범위: `X = 0..255`, `Y = 0..255`
- 화면 초기 상태: 검정색

논리 셀 하나는 RGB565 색상값 하나를 가진다. `VGA` 명령으로 일부 셀을 바꿀 때 다른 셀은 유지한다. 화면 전체를 지우는 동작은 초기 실행 또는 프롬프트의 `CLEAR`에서만 수행한다. `-loop`의 반복 경계에서는 화면을 초기화하지 않는다.

### 4.2 RGB565

색상은 16비트 RGB565로 저장한다.

```text
15             11 10                 5 4              0
+----------------+--------------------+----------------+
|    RED (5)     |     GREEN (6)      |    BLUE (5)    |
+----------------+--------------------+----------------+
```

| 색상 | RGB565 값 |
|---|---:|
| 검정 | `0x0000` |
| 빨강 | `0xF800` |
| 초록 | `0x07E0` |
| 파랑 | `0x001F` |
| 흰색 | `0xFFFF` |

### 4.3 `VGA` 명령의 좌표 패킹

첫 번째 입력은 상위 8비트를 Y, 하위 8비트를 X로 사용한다.

```text
INPUT1 = YYYYYYYY XXXXXXXX
          Y 좌표    X 좌표
INPUT2 = RRRRRGGGGGGBBBBB
          RGB565 색상
```

예를 들어 X=5, Y=10, 빨강은 다음과 같다.

```text
0110 0000101000000101 1111100000000000
     └── Y=10 ──┘└ X=5 ┘ └─ RGB565 ───┘
```

이 명령은 `(X=5, Y=10)` 셀을 빨간색으로 바꾼다. 명령 자체는 숫자 결과를 stdout에 출력하지 않는다.

## 5. OP 코드 — 고정 16개

OP 코드는 4비트이며 아래 번호를 고정한다. 다른 OP를 추가하려면 명령 필드 폭이나 규격 버전을 별도로 변경해야 한다.

| OP | 이름 | 입력 1 | 입력 2 | 기능 | 외부 출력 |
|---|---|---|---|---|---|
| `0000` | `PASS` | 값 | 무시 | 입력 1을 결과로 전달 | 텍스트 결과 |
| `0001` | `ADD` | 값 A | 값 B | 16비트 덧셈 | 텍스트 결과 |
| `0010` | `SUB` | 값 A | 값 B | 16비트 뺄셈 | 텍스트 결과 |
| `0011` | `MUL` | 값 A | 값 B | 곱셈의 하위 16비트 | 텍스트 결과 |
| `0100` | `DIV` | 피제수 | 제수 | unsigned 정수 나눗셈의 몫 | 텍스트 결과 |
| `0101` | `MOD` | 피제수 | 제수 | unsigned 정수 나눗셈의 나머지 | 텍스트 결과 |
| `0110` | `VGA` | Y/X 좌표 패킹 | RGB565 | 지정 셀에 픽셀 기록 | VGA만 |
| `0111` | `SHFL` | 다음 입력 1의 이력 인덱스 | 다음 입력 2의 이력 인덱스 | 다음 명령의 입력 연결 설정 | 내부 처리 |
| `1000` | `AND` | 비트값 A | 비트값 B | 비트 단위 AND | 텍스트 결과 |
| `1001` | `OR` | 비트값 A | 비트값 B | 비트 단위 OR | 텍스트 결과 |
| `1010` | `XOR` | 비트값 A | 비트값 B | 비트 단위 XOR | 텍스트 결과 |
| `1011` | `SHL` | 값 | 이동량 | 왼쪽 비트 이동 | 텍스트 결과 |
| `1100` | `SHR` | 값 | 이동량 | 오른쪽 논리 비트 이동 | 텍스트 결과 |
| `1101` | `BLEND` | RGB565 A | RGB565 B | 두 색상을 채널별 50:50 혼합 | 내부 색상 결과 |
| `1110` | `BRIGHT` | RGB565 색상 | 밝기 계수 | 색상 밝기 조절 | 내부 색상 결과 |
| `1111` | `CMP` | 값 A | 값 B | 비교 결과 생성 | 텍스트 결과 |

### 5.1 공통 수치 규칙

- 일반 수치 입력은 unsigned 16비트로 해석한다.
- 일반 연산의 결과는 16비트다. 범위를 넘는 결과는 하위 16비트만 유지한다.
- `SUB`의 언더플로는 16비트 래핑으로 처리한다. 예: `2 - 5 = 65533` (`0xFFFD`).
- `MUL`은 전체 곱의 하위 16비트만 결과로 사용한다.
- `SHL`과 `SHR`의 이동량이 16 이상이면 결과는 `0`이다. 이동량이 0이면 입력값을 그대로 반환한다.
- `SHR`은 최상위 비트에 0을 채우는 논리 오른쪽 이동이다.

### 5.2 OP별 상세 동작

#### `0000 PASS`

```text
OUT = INPUT1
```

입력 1을 그대로 결과로 만든다. 입력 2는 무시한다.

#### `0001 ADD`

```text
OUT = (INPUT1 + INPUT2) & 0xFFFF
```

두 값을 더하고 하위 16비트만 유지한다.

#### `0010 SUB`

```text
OUT = (INPUT1 - INPUT2) mod 65536
```

입력 1에서 입력 2를 뺀다. 음수 결과는 unsigned 16비트 래핑으로 표현한다.

#### `0011 MUL`

두 입력의 곱을 계산한 뒤 하위 16비트만 결과로 사용한다.

```text
OUT = (INPUT1 * INPUT2) & 0xFFFF
```

구현에서는 중간 곱셈이 충분히 넓은 정수형에서 수행되도록 한다.

#### `0100 DIV`

```text
OUT = INPUT1 / INPUT2
```

unsigned 정수 나눗셈의 몫을 반환한다. `INPUT2 == 0`이면 결과를 `0`으로 정하고 `stderr`에 진단 메시지를 출력한다. 이 경우에도 실행은 계속할 수 있지만, 실행 상태는 오류가 발생했음을 보고할 수 있어야 한다.

#### `0101 MOD`

```text
OUT = INPUT1 % INPUT2
```

unsigned 정수 나눗셈의 나머지를 반환한다. `INPUT2 == 0`이면 `DIV`와 동일하게 결과 `0` 및 `stderr` 진단을 사용한다.

#### `0110 VGA`

```text
INPUT1[15:8] = Y
INPUT1[7:0]  = X
INPUT2       = RGB565
```

지정 좌표의 셀을 지정 색상으로 덮어쓴다. 화면의 다른 셀은 변경하지 않는다. 텍스트 결과나 숫자 이력 결과를 만들지 않는다.

#### `0111 SHFL`

`SHFL`은 바로 다음 명령에서 사용할 입력값을 이전 계산 결과로 연결하는 보조 명령이다. `SHFL` 자체는 산술 결과를 만들지 않는다.

```text
SHFL INPUT1 INPUT2
     └─ 다음 명령의 INPUT1 이력 인덱스
          └─ 다음 명령의 INPUT2 이력 인덱스
```

각 필드의 의미:

| 인덱스 | 의미 |
|---:|---|
| `0` | 해당 입력은 명령에 기록된 원래 값을 그대로 사용 |
| `1` | 가장 최근의 결과 생성 명령의 결과 사용 |
| `2` | 두 번째로 최근의 결과 생성 명령의 결과 사용 |
| `3` | 세 번째로 최근의 결과 생성 명령의 결과 사용 |
| … | … |
| `65535` | 65535번째로 최근의 결과 생성 명령의 결과 사용 |

`SHFL`이 설정되면 다음 **비-SHFL 명령 하나**에 적용하고, 해당 명령 실행 후 두 선택값을 모두 0으로 되돌린다. 다음 명령이 오기 전에 `SHFL`이 다시 실행되면 최신 `SHFL` 설정이 이전 미사용 설정을 덮어쓴다.

이력에는 `PASS`, 산술·비트 연산, `CMP`, `BLEND`, `BRIGHT`의 결과가 순서대로 저장된다. `VGA`와 `SHFL`은 결과 이력에 추가되지 않는다.

요청한 이력 인덱스가 아직 존재하지 않으면 메모리 밖을 읽지 않는다. 해당 피연산자를 `0`으로 대체하고 오류 진단을 기록한다. 이 규칙은 결과 이력이 부족한 초기 실행에서도 동작을 결정적으로 유지한다.

#### `1000 AND`

```text
OUT = INPUT1 & INPUT2
```

각 비트가 양쪽 모두 1일 때만 결과 비트가 1이다.

#### `1001 OR`

```text
OUT = INPUT1 | INPUT2
```

각 비트 중 하나 이상이 1이면 결과 비트가 1이다.

#### `1010 XOR`

```text
OUT = INPUT1 ^ INPUT2
```

각 비트가 서로 다르면 1, 같으면 0이다.

#### `1011 SHL`

```text
OUT = (INPUT1 << INPUT2) & 0xFFFF
```

입력 1을 입력 2만큼 왼쪽으로 이동한다. 넘친 상위 비트는 버린다. 이동량이 16 이상이면 0이다.

#### `1100 SHR`

```text
OUT = INPUT1 >> INPUT2
```

unsigned 입력 1을 논리적으로 오른쪽으로 이동한다. 하위 비트는 버리며, 이동량이 16 이상이면 0이다.

#### `1101 BLEND`

입력 1과 입력 2를 RGB565 색상으로 해석하고, R/G/B 채널을 각각 50:50으로 혼합한다. 먼저 채널을 분리한 뒤 정수 계산을 하고, 각 채널의 소수 부분은 버린다.

```text
R = floor((R1 + R2) / 2)
G = floor((G1 + G2) / 2)
B = floor((B1 + B2) / 2)
OUT = pack_RGB565(R, G, B)
```

`BLEND`는 색상값을 이력에 기록하지만 직접 화면을 변경하지 않고 기본 텍스트 결과도 출력하지 않는다. 이후 `SHFL`로 결과를 `VGA`의 색상 입력에 전달한다.

#### `1110 BRIGHT`

입력 1은 RGB565 색상, 입력 2는 밝기 계수다. 밝기 계수는 `0..255` 범위로 제한한다. 0은 검정, 128은 약 절반 밝기, 255는 원래 밝기다.

채널마다 다음 정수 계산을 수행한다.

```text
factor = min(INPUT2, 255)
channel_out = floor(channel_in * factor / 255)
```

계산한 채널을 RGB565로 다시 패킹한다. 결과는 이력에 기록하지만 직접 화면을 바꾸거나 기본 텍스트 결과로 출력하지 않는다.

#### `1111 CMP`

입력 1과 입력 2를 unsigned 값으로 비교한다.

| 조건 | 결과 |
|---|---:|
| `INPUT1 < INPUT2` | `0` (`0x0000`) |
| `INPUT1 == INPUT2` | `1` (`0x0001`) |
| `INPUT1 > INPUT2` | `2` (`0x0002`) |

결과는 일반 숫자 연산처럼 텍스트로 출력하고 결과 이력에도 기록한다.

## 6. 결과 이력과 고정 메모리

`SHFL`이 과거 결과를 참조하려면 실행한 결과를 보관해야 한다. 이는 동적 할당 명령을 지원한다는 뜻이 아니다. 구현은 다음과 같은 **고정 크기 저장 영역**을 사용한다.

- VGA 논리 프레임버퍼: 256 × 256 × 2바이트 = 131,072바이트(128 KiB)
- 결과 이력: 65,536 × 2바이트 = 131,072바이트(128 KiB)
- 결과 이력은 원형 버퍼로 구현할 수 있다. 가장 최근 결과를 항상 유지하며, 이력이 가득 차면 가장 오래된 결과를 덮어쓴다.
- 이력 인덱스 `1..65535`는 각각 가장 최근부터 과거 방향의 결과를 의미한다.
- 이력은 프로세스 시작 시 초기화한다. `-loop` 반복 시작 시에는 초기화하지 않는다.

따라서 `16g`는 `new`/`malloc`에 의존하는 동적 작업 공간 없이 고정 버퍼로 동작할 수 있다. 다만 VGA 화면과 `SHFL`을 지원하려면 이 정도의 고정 메모리는 필수다.

## 7. `.16g` 바이너리 파일 형식

`.16g`는 **텍스트 스크립트가 아닌 바이너리 기계어 파일**이다. 아래의 16진수 표기는 파일 내용을 사람이 확인하기 위한 덤프 표기일 뿐, 파일에 ASCII 문자 `'0'`, `'1'`, `'A'` 등을 저장한다는 뜻이 아니다.

### 7.1 명령 레코드

각 명령은 5바이트로 저장한다.

| 바이트 위치 | 크기 | 내용 |
|---:|---:|---|
| 0 | 1바이트 | OP 코드 `0x00..0x0F` (상위 니블은 0이어야 함) |
| 1 | 1바이트 | INPUT1 상위 바이트 |
| 2 | 1바이트 | INPUT1 하위 바이트 |
| 3 | 1바이트 | INPUT2 상위 바이트 |
| 4 | 1바이트 | INPUT2 하위 바이트 |

16비트 입력은 **빅 엔디언(상위 바이트 우선)**이다. 예를 들어 입력값 `0x000A`는 파일에서 `00 0A`로 저장된다.

### 7.2 명령 사이 `&` 구분자

각 명령 레코드 사이에 실제 바이트 값 `0x26`(ASCII의 `&`에 해당하는 값) 하나를 둔다. 이는 텍스트 문자열이 아니라 바이너리 파일 안의 구분 바이트다.

- 명령 레코드: 5바이트
- 명령 사이 구분자: 1바이트 `0x26`
- 마지막 명령 뒤에는 구분자를 붙이지 않는다.
- 파일 파서는 5바이트 명령을 먼저 읽고, 파일에 데이터가 남아 있을 때만 그 다음 바이트가 `0x26`인지 확인한다. 따라서 피연산자 안에 값 `0x26`이 등장하더라도 명령 데이터와 구분자를 혼동하지 않는다.
- 구분자가 잘못되었거나, 파일이 명령 중간에서 끝나거나, OP 바이트 상위 니블이 0이 아니면 손상된 파일로 처리한다.

두 명령으로 구성된 예시의 **바이너리 바이트 덤프**:

```text
01 00 0A 00 03 26 02 00 0D 00 02
```

해석:

1. `01 00 0A 00 03` → `ADD(0x000A, 0x0003)`
2. `26` → 명령 구분자 `&`
3. `02 00 0D 00 02` → `SUB(0x000D, 0x0002)`

이 파일은 텍스트 편집기로 위 문자열을 입력해 만드는 것이 아니라, 위 값의 원시 바이트를 파일에 기록해서 만든다.

### 7.3 명령 파일 실행 순서

파일은 처음부터 끝까지 순서대로 실행한다. 명령 하나를 처리할 때마다 `SHFL`이 설정한 입력 대체 규칙을 적용하고, 결과 생성 명령의 결과 이력을 갱신한다. 정상적인 파일 끝에 도달하면 파일 실행을 마친다.

## 8. `-loop` 옵션

```bat
16g.exe -loop program.16g
16g.exe -hex -loop program.16g
```

`-loop`는 `.16g` 파일을 끝까지 실행한 다음 다시 첫 명령으로 돌아가 무한 반복한다.

**반복 경계에서 초기화하지 않는 항목:**

- VGA 프레임버퍼
- `SHFL`이 참조하는 결과 이력
- 아직 다음 명령에 적용되지 않은 `SHFL` 설정

프로그램 프로세스 시작 시에는 프레임버퍼를 검정색으로 한 번 초기화하고 결과 이력을 비운다. 그 뒤 반복 사이에는 이 초기화 과정을 다시 실행하지 않는다.

예를 들어 파일이 두 픽셀을 서로 다른 색으로 그리면 첫 번째 반복에서 그려진 픽셀은 후속 반복 중 다른 명령이 해당 위치를 변경하지 않는 한 유지된다.

`-loop`는 `.16g` 파일과 함께 사용하는 옵션이다. 파일 없이 `-loop`를 지정하면 인수 오류로 처리한다. 반복 실행을 끝내려면 VGA 창을 닫거나 호출 프로그램에서 프로세스를 종료한다.

> `-loop` 파일의 비그래픽 연산은 반복할 때마다 `stdout`에 결과를 기록한다. 호출 프로그램이 출력을 계속 저장하면 출력 파일이나 파이프가 커질 수 있으므로 주의한다.

## 9. 명령줄 사용 예시

| 명령 | 동작 |
|---|---|
| `16g.exe` | 콘솔 + VGA, 이진수 대화형 모드 |
| `16g.exe -hex` | 콘솔 + VGA, 16진수 대화형 모드 |
| `16g.exe 0001 0000000000001010 0000000000000011` | 단일 이진 명령 실행, VGA 창만 표시 |
| `16g.exe -hex 01 000A 0003` | 단일 16진수 명령 실행, VGA 창만 표시 |
| `16g.exe program.16g` | 바이너리 파일 한 번 실행, VGA 창만 표시 |
| `16g.exe -hex program.16g` | 파일 실행, 결과 표시는 16진수 |
| `16g.exe -loop program.16g` | 파일 무한 반복, 화면과 이력 유지 |
| `16g.exe -hex -loop program.16g` | 16진수 출력 모드로 파일 무한 반복 |
| `16g.exe -pipe` | VGA 창 + Named Pipe 서버, 외부 프로그램이 반복 명령 전송 |

옵션은 `-hex`, `-loop`, `-pipe`의 형태로 쓴다. `-loop`에는 반드시 `.16g` 파일을 제공한다. 파일 경로에 공백이 있으면 Windows 명령줄 규칙에 따라 따옴표로 감싼다.

### 9.1 외부 프로그램 자동화: Named Pipe

외부 프로그램이 `16g`에 명령을 계속 전달할 수 있도록 Windows Named Pipe 인터페이스를 제공한다. 파이프의 논리 이름은 **`16g`**이며, Windows에서 사용하는 전체 파이프 경로는 다음과 같다.

```text
\\.\pipe\16g
```

서버는 다음처럼 실행한다.

```bat
16g.exe -pipe
```

이 모드에서는 VGA 창을 표시하고, 콘솔 프롬프트 대신 파이프 연결을 기다린다. 다른 프로그램은 파이프에 연결한 뒤 명령 요청을 보내고 응답을 읽는다. 같은 서버 프로세스에 여러 클라이언트가 연결할 수 있으며, 명령은 한 번에 하나씩 순서대로 처리한다. 클라이언트 연결이 끊겨도 `16g` 프로세스와 VGA 화면, 결과 이력은 유지된다.

#### 요청 형식: 정확히 5바이트

한 명령은 다음 5바이트로 전송한다. 이 형식은 `.16g` 파일 형식과 별개인 IPC 전송 형식이다.

| 바이트 오프셋 | 크기 | 내용 |
|---:|---:|---|
| 0 | 1바이트 | OP 값 `0x00`~`0x0F` |
| 1~2 | 2바이트 | INPUT1, big-endian |
| 3~4 | 2바이트 | INPUT2, big-endian |

예를 들어 `ADD(10, 3)` 요청은 아래와 같다.

```text
01 00 0A 00 03
```

파이프는 바이트 스트림이므로, 한 번의 `ReadFile`이 반드시 5바이트 전체를 반환한다고 가정하면 안 된다. 구현은 요청 5바이트가 모두 도착할 때까지 읽어야 하며, 요청이 중간에서 끝나면 연결을 오류로 처리한다.

#### 응답 형식: 정확히 4바이트

각 요청마다 4바이트 응답을 반환한다.

| 바이트 오프셋 | 크기 | 내용 |
|---:|---:|---|
| 0 | 1바이트 | 상태 코드 |
| 1~2 | 2바이트 | 결과 값, big-endian |
| 3 | 1바이트 | 결과 종류 |

상태 코드 `0x00`은 성공, `0x01`은 경고를 동반한 완료(예: `DIV`/`MOD`에서 제수가 0이어서 결과를 0으로 정한 경우), `0x80`은 지원하지 않는 OP 또는 잘못된 요청, `0x81`은 내부 처리 오류를 뜻한다. 결과 종류는 `0x00` 숫자 결과, `0x01` 색상 중간 결과(`BLEND`/`BRIGHT`), `0x02` VGA 화면 변경, `0x03` 제어 명령(`SHFL`) 승인이다. 결과가 없는 종류의 응답에서 결과 값 필드는 0으로 설정한다.

숫자 결과가 있는 예시로, `ADD(10, 3)`은 다음과 같이 응답한다.

```text
00 00 0D 00
```

여기서 `00`은 성공, `00 0D`는 결과 13, 마지막 `00`은 숫자 결과를 의미한다. `VGA`와 `SHFL`은 숫자 결과를 반환하지 않으며, `BLEND`와 `BRIGHT`는 계산한 RGB565 값을 응답에 담아 반환한다.

#### 처리 순서와 보안

- 요청 하나를 처리하고 그 응답을 보낸 다음에 다음 요청을 처리한다. 따라서 `SHFL` 결과 이력의 순서는 파이프에 전달되어 실제로 처리된 명령 순서와 일치한다.
- 여러 클라이언트의 명령이 동시에 도착하면 서버가 정한 직렬 처리 순서대로 실행한다. 클라이언트가 여러 요청을 보낼 때는 각 요청에 대한 4바이트 응답을 읽고 다음 요청을 보내는 동기 방식을 기본으로 한다.
- 파이프 연결 종료는 명령 처리 상태, VGA 화면, 결과 이력을 초기화하지 않는다. 이 상태들은 서버 프로세스가 종료될 때까지 유지된다.
- 같은 이름의 서버가 이미 존재할 때는 중복 서버를 조용히 실행하지 말고 오류를 반환한다.
- Named Pipe의 보안 설명자(ACL)는 현재 Windows 사용자 등 허용된 로컬 사용자만 연결할 수 있도록 제한한다. 요청 버퍼 길이와 OP 범위를 검사하고, 불완전하거나 잘못된 요청을 실행하지 않는다.
- `-pipe` 모드에서는 숫자 결과를 바이너리 응답으로 전달한다. stdout의 텍스트 결과 형식과 혼용하지 않는다. 진단 문구는 stderr로 보낸다.

## 10. 출력 채널과 자동화 규칙

### `stdout`

비그래픽 숫자 결과를 한 줄에 하나씩 기록한다.

- 기본 모드: 16자리 이진수 + 줄바꿈
- `-hex` 모드: 4자리 대문자 16진수 + 줄바꿈

`PASS`, `ADD`, `SUB`, `MUL`, `DIV`, `MOD`, `AND`, `OR`, `XOR`, `SHL`, `SHR`, `CMP`가 결과를 텍스트로 출력한다. `BLEND`와 `BRIGHT`는 그래픽용 중간 결과로 취급하여 기본 stdout 출력은 하지 않는다. `VGA`와 `SHFL`도 출력 결과 문자열을 만들지 않는다.

대화형 모드에서는 시작 배너, 프롬프트, 도움말을 콘솔 텍스트로 표시한다. 자동화 모드에서 프로그램이 숫자 결과를 파싱하기 쉽도록 숫자 결과 외의 안내 문구를 stdout에 섞지 않는 것을 원칙으로 한다.

### `stderr`

형식 오류, 손상된 파일, 유효하지 않은 OP, 0으로 나누기, 존재하지 않는 `SHFL` 이력 참조 등 진단 메시지를 기록한다. 진단 문구는 VGA에 그리지 않는다.

### 종료와 오류 처리 권장안

- 잘못된 명령줄 인수 또는 입력 형식 오류: 실행을 시작하지 않고 오류 반환
- 손상된 `.16g` 파일: 안전하게 중단하고 오류 반환
- `DIV`/`MOD`의 0 나누기: 결과 `0`을 기록하고 진단 출력. 구현은 오류 상태도 호출자가 알아볼 수 있게 제공
- VGA 창 닫기: 프로세스 종료
- `-loop`: VGA 창을 닫거나 외부에서 프로세스를 종료할 때까지 반복

## 11. 구현 안전성과 검증 항목

구현 시 다음 규칙을 테스트해야 한다.

1. 모든 OP 코드는 정확히 4비트이며, 16개 이외의 OP를 실행하지 않는다.
2. 입력값의 길이와 숫자 범위를 확인한 뒤 실행한다.
3. `DIV`/`MOD`의 제수가 0인지 나눗셈 전에 검사한다.
4. `SHL`/`SHR` 이동량이 16 이상인 경우 C++의 정의되지 않은 동작에 의존하지 않고 0을 반환한다.
5. 16비트 래핑과 unsigned 해석을 모든 빌드 환경에서 동일하게 구현한다.
6. `SHFL` 이력 인덱스는 존재하는 결과 범위와 버퍼 용량을 확인한 뒤 접근한다.
7. `.16g` 파서는 매 레코드의 5바이트와 필수 `0x26` 구분 바이트를 검증한다.
8. 손상된 파일의 끝부분에서 버퍼 밖을 읽지 않는다.
9. `-loop` 반복 경계에서 VGA 화면, 결과 이력, 미사용 `SHFL` 설정을 재초기화하지 않는다.
10. VGA 렌더링은 논리 256 × 256 셀을 정확히 512 × 512 물리 픽셀 영역에 표시한다.
11. 텍스트, 경고, 디버그 문자열을 VGA 화면에 그리지 않는다.
12. 자동화 모드에서 stdout은 결과 데이터, stderr는 진단 메시지로 분리한다.
13. `-pipe` 모드는 `\\.\pipe\16g` Named Pipe를 사용하고, 요청 5바이트와 응답 4바이트 형식을 정확히 지킨다.
14. 파이프의 부분 읽기/쓰기, 클라이언트 연결 종료, 중복 서버 이름, 잘못된 OP 및 동시 클라이언트 요청을 검증한다.

## 12. 최종 요약

```text
프로그램 이름: 16g
OP 개수:       16
OP 폭:         4비트
입력 1:        16비트
입력 2:        16비트
논리 명령:     36비트
바이너리 저장: OP 1바이트 + 입력 1 2바이트 + 입력 2 2바이트
파일 구분자:   명령 레코드 사이의 0x26 바이트('&')
화면:          256 × 256 셀
셀 확대율:     2 × 2
실제 표시:     512 × 512 물리 픽셀
색상:          RGB565
결과 연결:     SHFL
반복 실행:     -loop
입출력 변경:   -hex
IPC 모드:      -pipe
파이프 이름:   16g
파이프 경로:   \\.\pipe\16g
요청 크기:     5바이트
응답 크기:     4바이트
```

`16g`의 처리 흐름은 다음과 같다.

```text
입력 명령 / .16g 파일
          │
          ▼
       OP 디코드
          │
          ▼
  SHFL 입력 대체 적용
          │
          ▼
   ┌──────┴───────────┐
   │                  │
숫자·색상 계산      VGA 픽셀 기록
   │                  │
   ├─ 결과 이력       └─ VGA 창
   └─ 숫자 결과 → stdout
      진단 메시지 → stderr
```

이 문서는 `16g`의 최종 기획 기준 사양이다. 실제 구현에서는 이 명령 번호와 데이터 형식을 임의로 바꾸지 않고, 형식 변경이 필요하다면 별도의 규격 버전을 정의한다.
